## Integrate crawl4ai for browser-based source discovery

```yaml
status: active
updated: 2026-08-01
horizon: near-term
```

Research completed; findings in `6.knowledge.md` (entry: "crawl4ai — research findings"). Plan document at `docs/plans/2026-08-01-crawl4ai-integration.md` (refreshed 2026-08-01 after merging `.arkitype/` extraction from master).

Key constraints confirmed from `.arkitype` extraction:
- `filters` values in `sources.json` are arrays of strings — CSS selector config must use flat string arrays.
- Registry dispatch is sync — new provider wraps `asyncio.run` internally.
- Only `requirements-dev.txt` exists for deps.

Implementation will:
1. Add a `crawl4ai_browser` discovery mode backed by `JsonCssExtractionStrategy` — deterministic, CSS-selector-based, zero LLM cost.
2. Consolidate cookie-consent dismissal boilerplate in `discover/sources/browser.py` into a shared helper.
3. Optionally expose `LLMExtractionStrategy` as a per-source opt-in for sources whose structure cannot be captured by CSS selectors (deferred).

This plan graduates to a project once a branch is opened and the first source migrated.

## Package tekt.observer as an installable Claude skills plugin

```yaml
status: active
updated: 2026-08-01
horizon: medium-term
```

Research completed; findings in `6.knowledge.md` (entry: "Claude skills packaging — research findings"). Plan document at `docs/plans/2026-08-01-claude-skills-packaging.md`. Roadmap item: RM-017.

The goal is to let someone use this job-search agent without cloning and understanding the full repo. Two phases:

**Phase 1 — Skills-only export (near-term)**

Add `scripts/install_skills.sh <target-dir>` that copies `.agents/skills/*/SKILL.md` into `<target-dir>/.claude/skills/` and writes a minimal `CLAUDE.md` stub pointing to the installed skills. No Python required; the agent gets instructions, the user is told they still need the scripts for execution.

**Phase 2 — MCP server (medium-term)**

Create `mcp/server.py` exposing `discover_jobs`, `run_track`, `rank_jobs`, and `install_skills` as MCP tools. Add `pyproject.toml` with `mcp>=1.0` dep and `tekt-observer-mcp` console script. Document `~/.claude.json` configuration.

Phase 1 unblocks skill-only users immediately. Phase 2 provides a complete one-install experience.

This plan graduates to a project when Phase 1 implementation begins.

## Integrate browser-use as a discovery driver for crawl4ai

```yaml
status: active
updated: 2026-08-02
horizon: medium-term
```

Research completed; findings in `6.knowledge.md` (entry: "browser-use — research findings"). Plan document at `docs/plans/2026-08-01-browser-use-integration.md`. Roadmap item: RM-018.

browser-use is an AI agent framework for browser automation. It complements crawl4ai: browser-use *discovers* how to navigate and extract from a page (reconnaissance), while crawl4ai *extracts at scale* using the CSS selectors and structure that browser-use identified.

Implementation will proceed in three phases:

**Phase 1 — Source-structure discovery driver (near-term)**

Add a `scripts/probe_with_browser_use.py` script that uses a browser-use agent to navigate a career page and output a structural description (CSS selectors for job cards, pagination mechanism, cookie-consent pattern). This output feeds into `sources.json` config for the `crawl4ai_browser` discovery mode. Depends on crawl4ai integration (RM-016) being at least Phase 1 complete.

**Phase 2 — Optional `browser_use` discovery mode (medium-term)**

Register a `browser_use` discovery mode in the provider registry for sources that require interactive multi-step navigation. The agent receives task instructions from `filters` in `sources.json` and returns structured job data. LLM cost is per-run; gated behind `requires = ("browser-use",)`.

**Phase 3 — tekt.observer as browser-use skills/plugin (medium-term)**

Package tekt.observer's `discover_jobs`, `evaluate_source`, `rank_jobs`, and `probe_source` capabilities as browser-use custom tools. Combined with crawl4ai extraction, this forms a complete open-source data-gathering plugin.

This plan graduates to a project once Phase 1 scripting begins and the crawl4ai integration is at least partially complete.
