The roadmap is maintained in `.knowledge/roadmap.md`. Active items and their sequencing:

### Near-term (next 1–2 sprints)

1. **RM-016** — Integrate crawl4ai for browser-based source discovery _(plan in `1.plans.md`)_
   - Enables RM-018 Layer 2 (sensor generation uses crawl4ai selectors)
   - Enables RM-019 Phase 1 (browser-use reconnaissance feeds crawl4ai config)
2. **RM-017** — Package as Claude skills plugin _(plan in `1.plans.md`)_
   - Phase 1 (skills export) unblocks RM-018 skill distribution

### Medium-term (next quarter)

3. **RM-018** — Multi-agent CLI platform with command phases _(plan in `1.plans.md`)_
   - Layer 1: Phase module scaffold and CLI entry point
   - Layer 2: Sensor auto-generation (depends on RM-016)
   - Layer 3: Source management interface (depends on Layers 1+2)
4. **RM-019** — browser-use as discovery driver for crawl4ai _(plan in `1.plans.md`)_
   - Phase 1: Reconnaissance script feeding CSS selectors into crawl4ai config (depends on RM-016 Phase 1)
   - Phase 2: Optional interactive `browser_use` discovery mode
   - Phase 3: Package tekt.observer capabilities as browser-use custom tools

### Dependencies

- RM-018 Layer 2 depends on RM-016 (crawl4ai provides CSS-selector-based exploration)
- RM-018 Layer 3 depends on RM-017 Phase 2 (MCP server enables web UI integration)
- RM-017 Phase 2 may use RM-018 phase abstractions for its tool definitions
- RM-019 Phase 1 depends on RM-016 Phase 1 (selectors feed the `crawl4ai_browser` mode)
- RM-019 Phase 1 naturally slots into RM-018's `/explore` phase (browser-use as an exploration driver alongside crawl4ai probing)
- RM-019 Phase 3 and RM-017 Phase 2 overlap (same tool surface exposed to browser-use and MCP) and should be coordinated
