
Scaffold the `phases/` Python module structure that provides the command-phase abstraction. Each phase is a callable with declared inputs/outputs. Deliverables:

- `scripts/phases/__init__.py` — Phase protocol definition
- `scripts/phases/explore.py` — `/explore` implementation wrapping crawl4ai probing
- `scripts/phases/seek.py` — `/seek` implementation for directed retrieval
- `scripts/phases/gather.py` — `/gather` implementation (refactored from `discover_jobs.py`)
- `scripts/phases/organize.py` — `/organize` schema-mapping logic
- `scripts/phases/understand.py` — `/understand` agent-driven analysis orchestration
- `scripts/phases/generate.py` — `/generate` output production (refactored from render/digest/delivery)
- CLI entry point exposing `tekt.observer <phase>` subcommands

Definition of done: All six phase modules exist with protocol conformance, the existing `run_track.sh` pipeline can be expressed as a gather→organize→understand→generate chain, and at least one source can be run through the full pipeline using the new CLI.

## Sensor auto-generation pipeline

```yaml
status: idea
updated: 2026-08-01
```

Automate the creation of source connectors ("sensors") from exploration results. When `/explore` identifies page structure (via crawl4ai CSS extraction or LLM-assisted analysis), produce:

- A sensor definition file (CSS selectors, pagination config, output schema)
- An optional Python provider stub registered in `discover/registry.py`
- Validation that the sensor produces expected output on the source's current page

This builds on the existing `source_integration.py` loop and `crawl4ai_browser` plan.

Definition of done: Given a URL and a target data type, the system can produce a working sensor definition that passes validation against live content without manual code authoring.
